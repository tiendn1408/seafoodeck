# Studio app on its own host — Implementation Plan (phase 2.5e)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Move every admin/manager/staff screen into a separate app (`apps/studio`, product name "Seafood Deck Studio") served on its own host `seafoodeckstudio.tiendn.io.vn`, so the learner app/host carries no trace of an admin area.

**Architecture:** Two Vite apps, one API, one DB, one web image holding both builds, one Caddy with two sites. `apps/studio` imports reusable learner modules from `apps/web/src` through a one-way `@web/*` alias (never the reverse; lint + CI enforced). The API adds `STUDIO_ORIGIN` to the accepted write origins and refuses wrong-realm logins with the generic wrong-password response. Learner host answers 404 for `/api/v1/admin*`, `/api/v1/manager*`, docs/openapi.

**Tech Stack:** React 19, Vite 8, TypeScript, NestJS, Caddy 2, Playwright, npm workspaces.

**Spec:** `docs/superpowers/specs/2026-11-25-studio-app-split-design.md` (incl. its Clarifications 1–8 — binding).

## Global Constraints
- Naming (owner, 2026-11-25): the staff app is **Studio** everywhere — folder `apps/studio`, package `@seafoodeck/studio`, shell `StudioApp`, env `STUDIO_ORIGIN`/`STUDIO_SITE_ADDRESS`/`STUDIO_WEB_PORT`, host `seafoodeckstudio.tiendn.io.vn`, UI title "Seafood Deck Studio". Unchanged by ruling: the DB/API role value `admin`, API paths `/api/v1/admin*` and `/api/v1/manager*`, and moved screen names (Admin, UsersAdmin, …) — renaming those needs a data migration and breaks deployed clients, outside this goal; they stay server-side/inside the studio bundle only.
- Hosts/env: learner `SITE_ADDRESS`/`PUBLIC_ORIGIN` = `seafoodeck.tiendn.io.vn`; studio `STUDIO_SITE_ADDRESS`/`STUDIO_ORIGIN` = `seafoodeckstudio.tiendn.io.vn`. Locally two distinct hosts (cookies ignore ports): learner `http://127.0.0.1:18089`, admin `http://localhost:18090` (`STUDIO_WEB_PORT`, default 18090). DNS and certificates for the studio host are the owner's job.
- Learner app/host must contain no admin trace: no word, route, link, file/chunk name, endpoint string or error message hinting an admin area exists. Plain TypeScript types are erased and don't count; runtime strings do (marker list: endpoint paths `/admin`, `/manager`; screen/component names; tab labels "Quản trị", "Người dùng", admin "Học viên"; `admin`/`manager` route names; chunk names).
- Realms: learner|student ↔ `PUBLIC_ORIGIN`; editor|reviewer|publisher|manager|admin ↔ `STUDIO_ORIGIN`. Wrong-realm login = same status/body/limiter cost as a wrong password. Unknown login Origin = same generic response. Absent Origin accepted on login and writes (scripts; CSRF still required) and tests assert it deliberately. `STUDIO_ORIGIN` unset ⇒ today's single-origin behaviour for all roles.
- Not a hardened boundary: no TOTP, no IP allow-list, no wildcard cert, no authenticated-only studio bundle. Server role checks (role × route matrix test) remain the boundary.
- Staff "Study" is not in the Studio app. Staff train with a personal student account on the learner host.
- Vietnamese UI copy; no new runtime dependencies beyond workspace wiring; Vitest/jsdom without @testing-library/react (`learner/testDom.ts`).
- Never touch other projects' containers; no `down`/volume removal; use this repo's local stack only (compose project `seafoodeck-pilot-acceptance`).

## Review Focus
1. Wrong-realm login (both directions), unknown Origin and absent Origin behave as specified; response bytes/status identical to wrong-password (T1).
2. After extraction the learner `dist` contains zero markers and the studio `dist` contains them; the marker script fails when a marker is planted in learner code (T3).
3. Reverse import `apps/web → apps/studio` fails lint and CI (T3).
4. Learner host `/api/v1/admin/users` answers exactly like an unknown path (same status and body shape) (T4/T5).
5. Studio app keeps forced password change, 401→login, CSRF rotation, leave guard + one-time-password panel, media preview/upload via S3 from the studio host (T2/T4/T5).

### Task 1: API — `STUDIO_ORIGIN`, write allow-list, realm-checked login
**Files:** Modify `apps/api/src/security.ts` (`Auth.checkWrite`, realm helpers), `apps/api/src/auth.controller.ts` (password + invite login), env: `deploy/pilot.env.example`, `deploy/env.example`, `deploy/ghcr.env.example`, `scripts/init-pilot.mjs`, `compose.yaml`, `deploy/compose.pilot.ghcr.yaml`, `deploy/compose.ghcr.yaml` (S3 `-s3.allowedOrigins` lists both origins if the flag accepts a comma list; else document), `README.md`; Test: `apps/api/src/realm.test.ts` (+ extend existing auth/security tests); `scripts/local-origin.test.mjs` only if needed (`localhost` is already loopback).
**Interfaces:**
- Produces: `realmOf(role: string): 'learner' | 'studio'`; `originRealm(origin: string | undefined): 'learner' | 'studio' | 'unknown' | 'none'` (`none` = header absent); `STUDIO_ORIGIN` env. `checkWrite`: CSRF as today; Origin present ⇒ must equal `PUBLIC_ORIGIN` or `STUDIO_ORIGIN` else 403 `Origin không hợp lệ.` (no realm match required on writes — spec decision; cookies are per host).
- Login: if Origin present and `STUDIO_ORIGIN` set, `originRealm(origin)` must equal `realmOf(account.role)` else respond exactly as a wrong password (same status/body, count against the login limiter). Unknown Origin on login ⇒ same generic response. Absent Origin ⇒ unchanged. `STUDIO_ORIGIN` unset ⇒ unchanged for everyone.
